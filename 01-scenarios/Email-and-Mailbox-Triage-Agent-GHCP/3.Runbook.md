# Shared Inbox and Request Processing Agent (GHCP) - Runbook

> Demonstrated with synthetic mail, bounded text attachments and approved test references. [Recorded results](0.Resources/Actual-test-record.json) include limitations, not production certification.

## 1. Prepare

Use an approved GHCP test environment, maker permissions and capped credits.
Check DLP/region. Choose a dedicated shared mailbox and licensed delegate.
Full Access is not read-only: restrict agent tools, grant no sending permissions
and block mailbox sign-in.

JSON files are **rebuild references, not importable solutions**. Use the supported designer.

## 2. Create the agent

1. Create a new GHCP agent in a separate test solution. Preserve the original agent.
2. Paste [Pilot-agent-instructions.txt](0.Resources/Pilot-agent-instructions.txt) into Instructions.
3. Under **Skills**, upload `Skills\shared-mailbox-intake\SKILL.md` and `Skills\grounded-reply-drafting\SKILL.md`.
4. Keep Microsoft authentication, memory/web search off and no channels. Record the model; this pilot used GPT-5.5 Chat.

## 3. Build the mailbox workflow

Open **Tools > Add > Workflow**. Use
[Fixed-mailbox-read.definition.json](0.Resources/Fixed-mailbox-read.definition.json)
as the field/expression reference. Build this sequence:

`When an agent calls the flow -> Get email -> Select -> Respond to the agent`

| Node | Configuration |
|---|---|
| Agent-call trigger | One required Text input, title `messageId` (generated key `text`). No mailbox input. |
| Office 365 Outlook Get email | Confirm operation `GetEmailV2`; bind the approved end-user connection. Message ID is the trigger input. Set Original mailbox address to the actual fixed test mailbox, replacing `__TEST_SHARED_MAILBOX__`. Include attachments and sensitivity-label flags: true. |
| Select | Copy `definition.actions.Select.inputs.from` and its four mapping expressions: `source_id`, `name`, `status`, `text`. Keep the node name Select. |
| Respond | Add the nine outputs below, in order. Copy corresponding expressions from `definition.actions.Respond_to_the_agent.inputs.body`. Under **More options > Settings > Run after**, select Succeeded, Failed, TimedOut and Skipped for Select. |

| Output title | Type / generated key |
|---|---|
| body | Text / text |
| source_id | Text / text_1 |
| subject | Text / text_2 |
| sender | Text / text_3 |
| has_attachments | Yes/No / boolean |
| status | Text / text_4 |
| error_code | Text / text_5 |
| attachments | Text / text_6 |
| attachment_status | Text / text_7 |

Use tokens/expressions, not quoted strings. Confirm `Get_email` and `Select` in
Code view; adjust mappings if generated keys differ.

Save and publish **the workflow only**. Attach it as `ReadSharedMailboxMessage`.
Remove any direct mailbox connector tool so it is not an alternate access path.

## 4. Build the reference lookup

Create a second agent-call workflow from
[Approved-reference-lookup.definition.json](0.Resources/Approved-reference-lookup.definition.json):
trigger -> Respond. Add one Text input `reference_id` (key `text`).
Add four Text outputs, in order: `status`, `source_id`, `text`, `version`.
Copy their corresponding response expressions; save/publish the workflow.
Attach it as `LookupApprovedReference`.

The catalogue is fictional, not company policy. Unknown keys return `not_found`.
Reload the saved agent: exactly two workflow tools, nine mailbox outputs and four
reference outputs.

## 5. Demonstrate the complete path

Seed approved [fixture messages](0.Resources/Synthetic-validation-cases.json);
attach actual files, not source text in chat.

For the received message ID, open an unsaved scratch workflow. Add Outlook
**Get emails (V3)** and configure Original mailbox address to the test mailbox,
Folder as custom value `Inbox`, Subject filter `CASE-001`, Top `2`, Fetch only
unread false and Include attachments false. Leave Search query blank.
Use **Run node > Run**, not the whole-flow Run. Inspect the result's subject and
copy its `id`; stop if zero/multiple matches. Discard the scratch workflow.
This verified maker-only selector is not an agent tool; Subject filter scans only
the first 250 messages, suitable for this small test mailbox. Do not substitute
an Outlook conversation URL.

Start a fresh Preview conversation with the [connected prompt](4.Sample-prompts.md),
supplying that ID but no message body or expected answer. Inspect the native
workflow trace: selected message -> conditional reference lookup -> review JSON.
Confirm exact source quotes, human review and no business writes.

Show normal policy, conflicting attachment and unsupported-file cases. Record
actual outcomes and failures. Full Access removal may not take effect immediately;
a successful read after removal does not prove denied-access handling.

## 6. Handoff and limits

Hand over these pages, skills, rebuild references and results; review scope with the recipient.

Supported attachments: up to five non-inline .txt files <=64KB each; no PDF/OCR.
Decoded-output limits do not bound upstream download volume. Outage/malformed
tests used controlled faults. Effective denial and complete skill attribution
remain unproven. Rebuild instructions are not a verified solution import.

Sending, routing actions, saved drafts and tasks remain disabled. Keep the agent
unpublished unless separately approved. A reproducible, demonstrated runbook with
honest limitations is distinct from production deployment approval.
