# Step-by-Step Guide - Autonomous Invoice Orchestration Agent (GitHub Copilot Harness)

> **Scenario**: Invoice processing, review and approval
> **Platform**: Copilot Studio, Power Automate Workflows, Outlook, SharePoint, Dataverse and Approvals
> **Target Readers**: Delivery engineer
> **Last Updated**: September 24, 2026

---

## Overview

This runbook recreates the implementation that was built conversationally in the GitHub Copilot
harness and then validated through live workflow runs:

**Receive PDF → save to SharePoint → call the agent → parse the 15-line review → save the review
and Dataverse record → notify finance or request human approval.**

Unlike the [original scenario](../Autonomous-Invoice-Orchestration-Agent/3.Runbook.md), this build
does not require separate parse, form-generation and approval flows. One workflow owns the
controlled actions, while one agent performs the document review.

| Location | Portal URL | Task |
|----------|------------|------|
| Copilot Studio | <https://copilotstudio.preview.microsoft.com> | Create, configure, test and publish the harness agent and workflow. |
| Power Platform admin center | <https://admin.powerplatform.microsoft.com> | Confirm the environment, capacity, policies and connections. |
| Microsoft 365 admin center | <https://admin.microsoft.com> | Confirm mailbox, SharePoint and user access where required. |

### Core Environment Requirements

| Requirement | Description |
|-------------|-------------|
| GitHub Copilot harness | Available in the target Copilot Studio environment. |
| Test mailbox | Receives digital PDF invoice attachments. |
| SharePoint storage | Library/folders for source invoices and review packages. |
| Dataverse | An **Auto Invoice Reviews** table or equivalent review table. |
| Microsoft Approvals | Available for the authorised approver. |
| Test documents | One incomplete invoice and one complete synthetic invoice. |

### License Requirements

Confirm Copilot Studio capacity and the licences required for Outlook, SharePoint, Dataverse,
Power Automate and Approvals in the target tenant. Licensing varies by environment and connector;
do not infer production entitlement from a successful test environment.

### Access and Permissions

| Identity | Minimum required access |
|----------|-------------------------|
| **Agent connection** | Read the designated SharePoint invoice location only. |
| **Workflow connections** | Read mailbox attachments, write the configured SharePoint locations and Dataverse table, send agreed notifications and create Approvals requests. |
| **Approver** | Receive and respond to the configured Approvals request. |
| **Maker** | Create, test and publish the agent and workflow in the selected environment. |

Begin with synthetic invoices. Do not use real bank details or confidential supplier data during
initial validation.

# Step-by-Step Instructions

## 1. Create the Agent Conversationally

In Copilot Studio, create an agent using the GitHub Copilot harness. Use this concise creation
request:

```text
Create an Invoice Orchestration Agent for Accounts Payable. A workflow will save an emailed
invoice PDF to SharePoint and provide the exact site URL and file path. The agent must read that
PDF, extract vendor, invoice number, dates, currency, subtotal, tax, total, purchase order,
accounting/GL code and billed-to entity, then flag missing or internally conflicting facts.
Return READY_FOR_APPROVAL only when there are no missing or conflicting facts; otherwise return
NEEDS_REVIEW. The agent must never approve, reject or pay an invoice and must not write to any
business system. Power Automate will own storage, Dataverse writes, notifications and the real
human approval.
```

The harness may propose tools and workflow steps. Review every proposed permission and action;
conversational creation accelerates authoring but does not remove the maker's responsibility to
verify the design.

**Expected:** a new agent shell and initial orchestration design.

## 2. Configure the Agent

1. Set the agent model to **GPT-5 Chat**, or an approved equivalent validated in the target
   environment.
2. Replace the generated instructions with
   [Agent-instructions.txt](0.Resources/Agent-instructions.txt).
3. Add the **SharePoint** tool and scope its connection to the intended invoice location.
4. Do not grant the agent Dataverse write, email send, approval or payment tools.
5. Leave **Knowledge** empty. The source of truth is the exact invoice PDF supplied at runtime.

**Expected:** the agent can read the specified PDF but cannot perform system writes or financial
actions.

## 3. Add the Invoice Review Skill

Upload [Skills/invoice-review/SKILL.md](Skills/invoice-review/SKILL.md) through:

**Build → Skills → Add skill**

The corrected skill matches this implementation: it reviews a PDF read directly from SharePoint.
It does not refer to the older `ParseInvoiceFlow`.

**Expected:** one skill named `invoice-review`.

## 4. Create the Intake and Approval Workflow

Create a workflow named **Invoice Intake and Approval Routing** with these top-level nodes:

| Order | Node | Purpose |
|------:|------|---------|
| 1 | **When a new email arrives** | Receive messages from the agreed mailbox scope. |
| 2 | **Initialize variables** | Prepare the agent response and parsed output variables. |
| 3 | **For each attachment** | Process supported attachments independently. |
| 4 | **PDF condition** | Continue only for an agreed PDF attachment. |
| 5 | **Save invoice PDF to SharePoint** | Preserve the original source before agent review. |
| 6 | **Call Invoice Orchestration Agent** | Supply subject, sender, site URL and exact file path. |
| 7 | **Parse response lines** | Split and map the fixed 15-line response into typed values. |
| 8 | **Save review package to SharePoint** | Preserve the agent response and review context. |
| 9 | **Create invoice review record** | Write the review to **Auto Invoice Reviews** in Dataverse. |
| 10 | **Decision condition** | Branch on missing/conflicting details or the parsed decision. |
| 11A | **Notify of invoice issues** | Send the `NEEDS_REVIEW` details to the agreed finance recipient. |
| 11B | **Request payment approval** | Start and wait for an authorised human approval. |
| 12 | **Approval outcome condition** | Branch on the actual Approvals result. |
| 13A | **Notify approval outcome** | Send the recorded approved result. |
| 13B | **Notify rejection outcome** | Send the recorded rejected result. |

## 5. Invoke the Agent with Exact Context

The agent invocation must identify one saved file. Include:

```text
Review the invoice PDF for this intake.
Email subject: <subject>
Email sender: <sender>
SharePoint site URL: <site URL>
SharePoint file path: <exact saved PDF path>
Return only the required 15-line response.
```

Do not ask the agent to search the mailbox or choose among invoices.

## 6. Parse the Agent Response

Split the response on line breaks and validate:

- exactly 15 non-empty lines;
- line 1 begins `INVOICE_KEY:`;
- line 2 is exactly `DECISION: READY_FOR_APPROVAL` or `DECISION: NEEDS_REVIEW`;
- each remaining line begins with its expected label;
- no field contains an unexpected embedded line break.

Map the values into workflow variables such as `invoice_key`, `decision_line` and `has_issues`.
If the response violates the contract, fail visibly or route it to review. Do not treat malformed
output as approval-ready.

## 7. Save the Evidence

1. Save the complete agent review package to the configured SharePoint review location.
2. Create the Dataverse review record with the invoice key, decision, extracted fields, issues,
   source link and review link.
3. Preserve the original source PDF and avoid overwriting a different invoice version.

Production deployments should enforce idempotency on message/attachment identity and invoice key.

## 8. Configure the Decision Branch

### `NEEDS_REVIEW`

Send a concise issue notification containing the invoice key, source link, review link and
reported issues. Do not create an approval request.

### `READY_FOR_APPROVAL`

Create a **Start and wait for an approval** action addressed to the authorised approver. Include
the extracted facts and source/review links. The approval title and details must make clear that
the agent review is not an approval recommendation.

## 9. Configure Approval Outcomes

Branch on the actual Approvals outcome:

- **Approve** → send the approval outcome notification.
- **Reject** → send the rejection outcome notification.

Do not infer an approval from the generated review, successful workflow execution or elapsed
time.

## 10. Publish and Test

Publish both the agent and workflow, then run the cases in
[4.Sample-prompts.md](4.Sample-prompts.md).

| Test | Expected workflow behaviour |
|------|-----------------------------|
| Missing required facts | `NEEDS_REVIEW`; issue email sent; approval actions skipped. |
| Complete, internally consistent invoice | `READY_FOR_APPROVAL`; live approval request sent. |
| Human approves | Approved branch and notification run. |
| Human rejects | Rejected branch and notification run. |
| Non-PDF attachment | Skipped or rejected according to the configured intake policy. |
| Malformed agent output | Visible failure/review; never routed as approval-ready. |
