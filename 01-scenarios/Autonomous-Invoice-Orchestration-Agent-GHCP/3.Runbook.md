# Runbook - Invoice Processing and Review (GHCP)

## Readiness

Normal intake/package components, replay protection and a mismatched-version
gate are demonstrated. Agent snapshot review passed after corrections, but
Preview inconsistently sees saved tools. **Do not present the Invoice live
agent-to-package path as ready.** Use recorded native component runs for training.
See [actual results](0.Resources/validation-record-template.json).

## 1. Approve the isolated setup

Confirm tenant, environment, model/credits, DLP, identity and synthetic content.
Use one test mailbox, a fixed SharePoint site and an owner/team-owned Dataverse
review table. No production resources, schedules or financial notifications.
Approve exact emails before seeding; never resend to recover a browser failure.

Create `Incoming` and `ReviewPackages` in the test Documents library. Create:

| Column | Type / maximum |
|---|---|
| Intake Key | Required text / 300 |
| Invoice Key | Optional text / 200 |
| Review State | Text / 40 |
| Source File Url, Package File Url | Text / 2000 each |
| Review Payload | Plain multiline / 100000 |

Create separate unique alternate keys on Intake Key and Invoice Key. Wait for
both indexes to become Active. Validate nonempty keys before effects; required
metadata and null alternate keys are not execution guards.

## 2. Rebuild the bounded workflows

Use the supported GHCP workflow designer and these **reconstruction references,
not importable solution files**:

| Workflow | Definition and inputs |
|---|---|
| Operator intake | [Invoice intake](0.Resources/Invoice-intake.definition.json); Text `messageId`, internal `text` |
| `ReadInvoiceMessage` | [Record read](0.Resources/Invoice-record-read.definition.json); Text `record_id`, internal `text` |
| `LookupFinanceReference` | [Finance reference](0.Resources/Finance-reference.definition.json); Text `reference_id`, internal `text` |
| `GeneratePaymentFormFlow` | [Generate review package](0.Resources/Generate-review-package.definition.json); Text `record_id` and `expected_version`, internal `text` and `text_1` |

Recreate named actions, expressions, branches and failure run-after settings
exactly from each definition. Map the publisher-prefixed table/column names.
Replace fixed-resource placeholders and bind approved end-user connections.
Set `DENIED_ROW_ID` to the all-zero GUID, never a real row. Keep explicit
received-message/source-record allow-lists; do not make paths or tables
model-supplied. The included reader/generator references permit one source row.

Use Dataverse **selected-environment** operations with the fixed organization:
`CreateRecordWithOrganization`, `UpdateOnlyRecordWithOrganization` and
`ListRecordsWithOrganization`. The implicit current-environment route failed
authentication in this pilot. Explicit OAuth alone did not repair that route.

Intake claims its unique key before saving original attachment bytes and the
source snapshot. Generation reads that snapshot, compares the expected source
version, parses supported English AUD lines and checks approved fictional rules.
It creates a SEPARATE package-claim row before writing the review JSON file.
Package identity excludes amount/currency. Replays reconcile rather than retry
the file write. A review file is never approval or payment authority.

Generator exceptions remain incomplete outside demonstrated scope: malformed
amounts may fail before a claim; unsupported input classification and concurrent
source-edit protection need further work. Do not enable broader inputs by assumption.

Save and publish only approved on-demand workflows. Native green run status can
mean a handled `denied` result; inspect the returned business status.

## 3. Configure the unpublished agent

Choose the test solution before first save. Use Microsoft authentication.
Keep web search, memory, external channels and other-agent access off.
Import the two files under `Skills/`, then attach the three agent-facing
workflows above. Do not attach operator intake as a read tool.
Use [pilot instructions](0.Resources/Pilot-agent-instructions.txt).

Read outputs, in order: `status`, `source_id`, `record_json`, `version`.
The source text is inside `record_json.cr090_reviewpayload`, another JSON value.
Use its actual message/attachment IDs for citations. This is a stored snapshot,
not a fresh mailbox read. Reference bundles return the six approved fictional
entries; unknown keys return `not_found`. Generator outputs are `status`,
`record_id`, `result_json`, `version`; read its reconciled package result.

## 4. Operate and demonstrate

Run operator intake once for an approved selected message. Record its row ID.
In Preview, request review using that row ID, without pasting source text or
expected answers. Inspect actual read, reference and generator calls.
Confirm exact citations, package URL/state, human review and `not_requested`.

Replaying the existing package should return `duplicate`, not create another.
An incorrect expected version must stop before claim. Preserve every failed
attempt. Stop repeated prompts if saved tools remain unavailable; the
[documented refresh pattern](https://learn.microsoft.com/en-us/microsoft-copilot-studio/agents-experience/authoring-test-bot)
was tried and did not reliably resolve this pilot's mismatch.

## 5. Close the handoff

Review the runbook, evidence and limitations with the owner. Complete remaining
cases before sign-off. Remove temporary build privileges and verify operator
access; any replacement role needs separate scoped approval.
Keep approval notifications OFF. Their exact recipient/content, authoritative
decision/version handling and tests remain a separate gate. Never post or pay.
