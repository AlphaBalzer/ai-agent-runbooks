# Finance Document Processing and Approval Agent (GHCP)

> Scope: invoice-only adaptation of the original [Autonomous Invoice Orchestration Agent](../Autonomous-Invoice-Orchestration-Agent/1.Overview.md).
> Status: unpublished pilot; normal intake/package components demonstrated. Agent snapshot review works inconsistently; end-to-end generation and approval remain unproven.
> Source guidance: September 16; component evidence: September 21, 2026.

## Purpose

Keep the original intake -> save -> parse -> form -> approval process and
SharePoint/Dataverse design. The [architecture](2.Architecture.md) maps the original
flow names to their steps; these are design labels, not supplied exports.

The [matrix](0.Resources/Capability-matrix.md) separates two runtime skills from
intake/save and human-approval workflow stages.

Add source-linked extraction and targeted reference lookup to resolve gaps or
conflicts before preparing the form or an exception. Financial checks remain
deterministic and approval remains human-owned.

Reuse approved test flows if present; otherwise implementation is still required.

## Boundaries

In scope:

- Supplier invoices with readable email or attachment text.
- Original storage and transaction/state design, with any missing arithmetic,
  duplicate and permission checks added in the workflows, not assumed implemented.
- Cited extraction, missing/conflicting data flags, and human review for all packages, including `ok`.
- [Shared Inbox companion](../Email-and-Mailbox-Triage-Agent-GHCP/1.Overview.md) is related, not a prerequisite.

Out of scope:

- Expense claims, credit notes, statements, remittance, bank changes, ERP posting or payment execution.
- Broad mailbox search, arbitrary HTTP, generic Dataverse CRUD, generic MCP access, new bespoke backend platform, or mandatory OCR.
- Hardcoded model selection, tenant screenshots, internal names, private plans, customer numbers or production identities.

## Outcomes

| Outcome | Meaning |
|---|---|
| `ok` | Evidence and deterministic checks passed, package still needs human review |
| `needs_review` | Missing evidence, conflict, invalid reference, policy exception or material edit |
| `denied` | Caller or execution identity is not authorized |
| `unavailable` | Required connector, table, library or approval state is unavailable |
| `unsupported_input` | Attachment/content is outside readable invoice scope |
| `duplicate` | Intake retry or duplicate business invoice detected |
| `pending` | Approval or workflow has not reached a terminal state |
| `failed` | Known operation failure |
| `unknown_outcome` | A write may have succeeded; reconcile before retry, never report success |
| `capability_disabled` | Requested capability is intentionally off |

`pending` is not `approved`. Approval is valid only when the controlled workflow records raw `Approve` or `Reject` from an authorized principal for the reviewed record version. Material changes invalidate prior approval and require review again.

Defer trigger wiring until selected-item testing works. Approval notifications
stay OFF pending separate approval. A content walkthrough is not integration proof.
