# Sample Prompts - Autonomous Invoice Orchestration Agent (GHCP)

Use a synthetic digital PDF, starting with the original [sample invoice](../Autonomous-Invoice-Orchestration-Agent/0.Resources/Sample_Invoice.pdf).
These examples describe the simplified PDF build target, **not capabilities already deployed**.
See [delivery status](0.Resources/README.md#delivery-status) for the existing text-based evidence.

| User Goal | Sample Prompt | Expected behavior after the flows are configured |
|---|---|---|
| Process an invoice | Process the invoice I emailed and prepare its payment request. | Use the transaction provided by intake, extract the PDF and prepare the form. |
| Supply accounting details | Use GL Code 6100 and Cost Center CC-204, after checking the approved reference. | Verify the supplied codes rather than blindly accepting them. |
| Review before action | What information is missing from this invoice? | Use the invoice-review skill to explain gaps or failed reference findings and stop rather than guessing. |
| Create the form | Create the payment request for the invoice we have reviewed. | Use the actual extracted data and return the workflow's saved form link. |
| Send for approval | Send this reviewed request to the authorized manager. | Use the separately enabled approval workflow after the required confirmation. |
| Check the outcome | Has this payment request been approved? | Report the recorded decision, or pending/unavailable; do not infer approval. |

Users should not need to edit a Message Id allow-list. The configured intake selects the
transaction; ambiguous requests need clarification rather than a guessed invoice.
Use the [agent instructions](0.Resources/Agent-instructions.txt) and
[single review skill](Skills/invoice-review/SKILL.md), not the older archived pilot payloads.

## Example Interactions

**User:** Process the PDF invoice I emailed and prepare its payment request.

**Expected:** the original PDF is saved, document extraction returns its fields, the GHCP
review skill checks them, and the form workflow returns the saved HTML form. Missing or
conflicting facts are explained before approval is requested.

**User:** The invoice total and the extracted line items disagree.

**Expected:** preserve both values and their evidence, stop the normal handoff and ask the
finance reviewer to resolve the discrepancy. Do not choose whichever value makes the form pass.

**User:** Send it for manager approval.

**Expected:** only the enabled approval workflow can submit the reviewed request. Until it is
implemented, report that limitation and send nothing. After submission, pending is not approved.

## Outputs

| Output | What to show |
|---|---|
| Source | The actual emailed PDF saved in SharePoint. |
| Extraction | Invoice details linked to that PDF, with missing values explicit. |
| GHCP review | A short explanation of checks and unresolved questions. |
| Payment request | Saved HTML form with the correct invoice information. |
| Approval and notification | Real authorized decision, persisted status and actual notification outcome. |

Use a normal PDF case, a missing/conflicting-data case and a rejected request for the initial
walkthrough. Record what actually ran. The original screenshots and earlier text-pilot runs
are not evidence of the simplified PDF path.
