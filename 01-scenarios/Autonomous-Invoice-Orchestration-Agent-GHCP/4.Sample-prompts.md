# Sample Prompts - Autonomous Invoice Orchestration Agent (GHCP)

Use the [synthetic cases](0.Resources/synthetic-invoice-fixtures.json) and an authorized intake
record. These follow the [standard user goals](../Autonomous-Invoice-Orchestration-Agent/4.Sample-prompt.md).
They are expected examples, not executed results. Check [delivery status](0.Resources/README.md#delivery-status):
the complete agent path is blocked and approval is not enabled.

| User Goal | Sample Prompt | What the Agent Does |
|---|---|---|
| Start invoice processing | Review invoice record `<source-row-id>` and prepare its payment request form. | Reads the saved invoice, cites evidence and checks references before permitted generation. |
| Process an invoice with accounting details | Review `<source-row-id>`. Check GL Code 6100 and Cost Center CC-204 before preparing the form. | Validates the proposed codes against approved records. |
| Create only the payment form | Generate the payment request for reviewed record `<source-row-id>` using its current version. | Requests workflow validation/generation and reports the actual result. |
| Send for approval | Send this reviewed payment request to its authorized approver. | Uses a separately enabled approval workflow. In the supplied configuration, reports disabled and sends nothing. |
| Check invoice status | Check the status of request `<record-id>`. | Reads recorded state without restarting work, or explains that no status reader is configured. |
| Review extracted invoice details | Show the key invoice details and source evidence for `<source-row-id>`. | Returns supported values and flags gaps or conflicts. |
| Ask what to do next | What information is missing from this invoice request? | Explains what the responsible person needs to resolve. |
| Confirm approval outcome | Has payment request `<record-id>` been approved? | Reads an authoritative current-version decision when configured; never infers approval from a form. |

Replace placeholders with actual intake/package IDs. Fixture IDs are test labels, not Outlook
message IDs or permission to search the mailbox.

## Example Interactions

### A supported invoice

This is an **illustrative interaction**, not a successful end-to-end run transcript.

**User:** Review the invoice already saved as record `<source-row-id>`. Check GL Code 6100 and
Cost Center CC-204 and prepare the payment request form. Do not start approval.

**Expected response:** If workflow validation and generation succeed, return the actual form
URL, record/version, findings and source evidence. Human review is still required; approval
has not been requested.

The normal PO fixture is 2 x AUD 50 + AUD 10 tax = AUD 110. Cite `att-normal-001` and the used
reference IDs. Model arithmetic does not prove workflow validation.

**User:** Now send it for approval.

**Expected response in the supplied configuration:** Approval is disabled; nothing was sent.
Any actually saved review package remains available for human review.

### Missing or conflicting information

**User:** The email and attachment disagree about the total. Which amount should we use?

**Expected response:** Show both source values and quotes, return `needs_review`, and ask the
responsible finance user to resolve the conflict. Do not select a total or mark the request
approved.

### Disabled or failed steps

Generation OFF returns `capability_disabled`, retaining read findings but no new form URL.
After partial failure, preserve known file/row IDs and reconcile before retrying. An unresolved
write is `unknown_outcome`, not permission to create another file.

## Outputs

| Output | What to inspect |
|---|---|
| **Source invoice** | Original attachment in SharePoint, its actual source IDs and linked Dataverse record. |
| **Extraction and reference findings** | Exact quotes, candidate fields, approved reference IDs and missing/conflicting facts. |
| **Payment request form** | Actual saved artifact, validation results and current record/version. The supplied component creates review JSON, not HTML. |
| **Approval request and outcome** | Actual request ID, authorized responder and decision for the current version; not a seeded fixture or model statement. |
| **Transaction record** | Processing status and links to the source and generated form. |
| **Notifications** | Agreed recipients and actual delivery evidence when those actions have been implemented and enabled. |

The [saved instructions](0.Resources/Pilot-agent-instructions.txt) define the 15-field response.
`requires_human_review` remains true. Read the business status, not only a green workflow badge.

### Additional test cases

Cover missing/unsupported input, invalid codes, conflicting totals, malicious instructions,
duplicates, access failure, pending/rejected decisions and material source changes using the
[starter cases](0.Resources/synthetic-invoice-fixtures.json).
The [results record](0.Resources/validation-record-template.json) separates component observations
from complete-case acceptance. [Test guidance](0.Resources/README.md#test-guidance) covers setup,
repeats and concurrency.
