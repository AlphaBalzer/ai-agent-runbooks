GHCP SCENARIOS: TRAINER QUICKSTART
Finance guidance updated 23 September 2026; Shared Inbox notes below are the 21 September snapshot.
Training guidance, not release sign-off.

THE ONE-SENTENCE EXPLANATION
The agent investigates and explains evidence; workflows enforce fixed actions;
a person retains authority. A review package is not an approval or a payment.

WHAT YOU CAN TEACH NOW
Shared Inbox: a bounded connected demonstration, with recorded normal,
conflicting, malicious, unsupported and controlled-failure cases.
Invoice: teach the original PDF process with one small GHCP review skill.
Prepare the original supporting flows first; show agent creation, instructions,
one skill upload and tool connections live. This is a prepared-environment exercise,
not a full blank-screen deployment. The simplified PDF path is not yet demonstrated.

20-MINUTE SESSION
0-3 minutes: Explain scenario versus skill versus technical pattern.
  Scenario: the business result.
  Skill: reusable reasoning/procedure instructions.
  Pattern: reusable connectors, scoped workflows and storage controls.
3-10 minutes: Shared Inbox.
  Open its Runbook, then the configured unpublished agent's Preview.
  Select the existing approved normal message; paste the sample prompt.
  Show the source read, reference lookup, exact citations and human-review flag.
  Show the recorded conflicting-attachment example.
  Point out that no message is sent, moved, deleted or marked by the agent.
10-17 minutes: Invoice, clearly labelled BUILD TARGET until rehearsed.
  Explain: PDF arrives, save, extract, create payment request, approve, notify.
  Show the original supporting-flow sequence and where the GHCP review belongs.
  Open the new Agent-instructions.txt and Skills/invoice-review/SKILL.md.
  The skill reviews extraction/reference results; it introduces no extra service.
  If showing the existing text-to-HTML recording, label it as the earlier pilot,
  not proof of the PDF-to-approval path. Do not rebuild archived JSON on stage.
17-20 minutes: Explain boundaries and questions.
  All packages require a person. Invoice approval notifications are off. No payments,
  posting, bank changes, production data or hidden generic write tools.

SIMPLE OPERATOR ROUTINE
1. Confirm the approved test identity, environment and existing fixture.
2. Use the supplied prompt or recorded run, not a newly composed test email.
3. Inspect business status and evidence, not just a green workflow badge.
4. Stop on denied, unavailable, failed or unknown_outcome. Reconcile writes
   before retry. A duplicate is the safeguard working, not another success write.

REHEARSAL AND STOP RULE
Rehearse the exact live path before training. Do not spend an audience's time
debugging Preview. If a configured tool is reported unavailable, use the recorded
native run for illustration and call the live path blocked. Never substitute
a model-only answer and describe it as connected execution.

LIMITS TO SAY OUT LOUD
Synthetic references, not live enterprise policy or ERP data.
The earlier recordings use bounded text attachments, not PDF/OCR. Some faults were deliberately injected.
Effective mailbox denial after immediate revocation remains unproven.
Independent completion of the earlier pilots' two skills is not established.
Earlier Invoice text-pilot non-normal, concurrency and partial-write coverage is incomplete;
its replay also shortened source citation IDs. Preserve that limitation.
Archived rebuild JSON is optional history, not a solution import or a GHCP requirement.

RELEASE GATE
Invoice finish line: one PDF email through extraction, GHCP review, actual form,
real authorized manager decision and recorded notification. Rehearse the normal,
missing-information and rejected cases. The earlier text pilot's successful HTML
creation/replay does not complete the simplified PDF build.
Training materials or local packaging do not authorize public sharing or release.
